PLC PORTAL / INFORMATION ARCHITECTURE

全員で勝つ。
自分の歩みから、次の活動へ。

PLCポータルを唯一のトップとし、その配下に5つの活動エリアを置く。次にやることはエリアを横断する行動ガイド。PLCプロフィールは本人の写真・分身・成長・実績をまとめる「自分を育てる場所」とする。2026年10月6日の会話に基づく設計と操作デモ。

v0.11：顔となるホームと、迷わない操作

ホームの大見出しは「全員で勝つ」の1回だけ。句点の別色装飾と上部の重複コピーを除去。挨拶は補助にして、活動状況と5つの行き先を主役にする。共通メニューはPC15pxを基準に、重要な本文は14〜16pxへ拡大。淡すぎる小文字を減らす。

「クエスト」は画面上で「次にやること」に変更し、プロフィールと自分を育てる場所を「マイプロフィール」に統合する。各エリアの未完了件数→そのエリアに絞った活動一覧→具体的な行動という経路を共通にする。件数は同じ活動データから計算する。達成判定はまだ固定の架空データであり、実ポイントを自動付与しない。

右上の本人メニューにプロフィールとログアウト。デモのログアウトはこのタブの体験状態だけを切り替え、ログイン画面から再開できる。実認証やMCP認可は変更しない。本番では会員のログイン状態、期限切れ、再認証、戻り先を認証基盤に接続して検証する。

5つの新規背景は組込み画像生成で個別制作し、色だけでなく学校・工房・広場・相談施設・本人のアトリエとして景色を描き分けた。配信画像はJPEG化。ホームのカードは専用の軽量画像を遅延読込みし、背景用の大きい画像は各エリアで使用。本人アイコンも専用サイズに縮小して配信する。地図は静止画＋HTMLで、3D描画・歩行は追加しない。「日本一」などの優位性は未検証であり、本人・スタッフの実操作で迷い・可読性・操作数を評価する。

1. 名前と親子関係

PLCポータル：全体の入口・会員認証・自分の活動状況
├ 学ぶ → PLCコンテンツ（学校・教室・教材・素材ライブラリー）
├ ツールを探す → PLCツール（工房・AI・リサーチ・便利ツール）
├ 交流する → PLCキャンパス（広場・部屋・チーム・仲間）
├ サポートを受ける → PLCサポート（相談・グルコン・イベント・利用枠）
└ マイプロフィール → PLCプロフィール（写真・分身・ジョブ・成長・実績）
横断：次にやること → 各エリアで行動 → 達成をプロフィールへ

「PLC AIポータル」は独立した親サイト名として使わない。田中祐一AIはPLCツール内のサービス名。PLCキャンパスは交流エリアの名称で、トップ全体とは区別する。「PLCアバター」は本人から独立した会員管理の単位にしない。

2. トップに表示すること

本人の活動状況（成長レベル・累計LTT・今期T・在籍日数）、学習の続き、残っている活動ロードマップ、使えるサポートを入口にする。5つのエリアへの大きなカードと、素材集への近道を配置する。活動が少ない人には順位の低さを強調せず、本人に合う次の一歩を案内する。ランキングの詳細は交流エリアへ。

3. 階層と移動の共通ルール

  1. どこでも共通メニューからホーム・5エリア・活動ロードマップへ移動できる。スマホは常に見える「メニュー」ボタンで全項目を開き、トップの大きなカードも併用する。横スクロールの見切れだけに頼らない。
  2. 「PLCポータル → 学ぶ → 講座づくりの教室 → 教材」の現在地を表示し、途中の階層へ直接戻れる。ブラウザの戻る・進むとページの直接URLを使える。
  3. エリアごとの2Dマップは「場所を選ぶ入口」。実作業は教室・部屋のカードと詳細画面で行う。歩行や3D回転で待たせない。
  4. 各マップと一覧は同じ情報・行き先を使い、エリアごとに表示の好みを記憶する。学習済み・会員資格による公開制御も同じ条件にする。
  5. 教材→関連素材→ツール→相談→交流などの近道を設ける。同じ資料をカテゴリごとに複製しない。
  6. 本人用プロフィールの編集、他の会員が見る公開プロフィール、運営確認画面を分ける。本番では未保存編集の離脱確認、キーボードのフォーカス、視聴位置の復元も扱う。

「学ぶ」は学校の2Dマップから教室へ入り、教材をカードで選ぶ。「交流する」のマップからは現在の部屋デモへ進む。現在の各エリア地図には、5種類の異なる風景を使用。学校は青、工房は琥珀、交流は緑、サポートは珊瑚、プロフィールは紫で、ホームのカード・現在地・ボタン・背景を揃える。最終アートでは学校・工房・広場・サポートハウス・自分のアトリエを同じ世界観で描き分ける。

5. 現在の素材集をどこへ置くか

正式な置き場所は「学ぶ → 素材ライブラリー（現在の素材集）」とする案。トップ・ツール・サポート・各教材には近道を置く。素材は「読む・使うファイル」、ツールは「実行・作業する機能」として整理する。

  • PDF・テンプレート・チェックリスト・記入用ファイル：素材ライブラリー。
  • 動画・講義・解説記事：PLCコンテンツの教室またはアーカイブ。
  • 45日シート：入力・管理の機能はツール。記入見本・解説は学ぶ／素材から参照。
  • グルコン：参加や利用枠はサポート。録画・議事録は学ぶのアーカイブ。同一イベントIDで相互参照。
  • AIスキル：実行・導入はツール、使い方は学ぶへ。素材のダウンロードと混同しない。

別スレッドの移植担当に渡す項目：原本ID、移植先ID、タイトル、種別、テーマ、関連講座・イベントID、更新日、対象会員、公開可否、ファイル/本文、旧URL、新URL。現在の素材集の全件棚卸しは本タスクでは未実施。実物を分類して例外を確認する。移植担当へのメッセージ送信は行っていない。

6. PLCプロフィールは「本人の成長」を扱う

本人の写真から作る専用アバターを、本人の分身として使う。画風見本6種類を選ばせる方式ではない。費用は運営負担。写真の更新・分身の確認・再生成、メイン/サブジョブ、得意分野、募集中の相手、成果・貢献履歴、称号や装備をまとめる。

表示意味
成長レベル／成長ランク本人が積み重ねた実践と貢献。3ヶ月でリセットしない。名称と閾値は運営と確定。
累計LTT生涯の評価の蓄積。今期のランキングと区別。
今期T・今期順位3ヶ月期間内の対象活動のみ。同点は同順位。
在籍日数継続の情報。実力や今期の活動量の代わりにしない。
ジョブ／運営・認定資格本人が示す活動分野と、運営が付与する資格は別管理。点数だけで認定講師にしない。

「ランク」は成長ランク、「ランキング」は今期順位とラベルを分ける。プロフィールに人物の全情報を無条件公開しない。写真原本、連絡先、個別相談内容は公開プロフィールから分離する。退会時の非表示は既存仕様に従う。

7. 次にやることは各エリアを横断する

「まだ使えていない学びやサポート」「進めている実践」「仲間へ貢献できること」を次の行動として提示する。トップにおすすめを最大3件、活動ロードマップ一覧に対象全件を表示する。未達成を罪悪感や強制の演出にしない。見送る・興味なし・通知OFFも本番で用意する。

未着手 → 進行中 → 確認が必要なら承認待ち → 達成
差戻し → 修正して再提出 ／ 対象外・期限終了は別表示
活動ロードマップを選ぶ → 学ぶ・ツール・交流・サポート・プロフィールで行動 → 条件確認 → 実績・LTT・対象期間Tへ反映

活動ロードマップ名、対象会員・前提条件、目的、関連リソース、行き先、達成条件、判定方式、配点ルール、期限、繰り返し周期、状態、根拠イベント、運営確認者を持つ。活動ロードマップと実行機能を別管理し、同じ教材や相談を複数活動ロードマップから案内しても二重加点しない。

  • 学習：Cloudflareの重複を除く視聴区間が70％に達したら一度だけ。完了ボタンだけで加点しない。
  • 相談・イベント：申込ではなく参加・利用実績で判定。利用枠や対象資格を照合。
  • 部活動：参加と、成果物を完成させた完遂を分けて評価。
  • ナレッジ提供：出典・利用範囲・重複確認後の承認で貢献を高く評価。
  • プロフィール：初回設定を案内。更新連打でポイントを増やさない。
  • ツール利用：接続回数・プロンプト数を無制限に得点化しない。意味のある達成条件を選ぶ。

本番の完了判定・ポイント付与はサーバー側の活動台帳を根拠とする。複数活動ロードマップで同じ根拠イベントを共有する場合、活動・会員・配点ルール・評価段階の一意性を確認する。二重申請、退会、承認取消、シーズン境界、繰り返し活動ロードマップをテストする。承認待ちポイントは確定ポイントに混ぜない。

8. 本番データと画面の対応

全体の共通キーは会員ID。活動イベント、ポイント台帳、活動ロードマップ定義/会員進捗、プロフィール、教材、素材、ツール、支援資格/予約/利用、Chatworkアカウント対応を分けて保持する。マップと一覧は同じリソースを参照し、権限も共通化する。PoCのSupabaseを移行する際は原本IDと会員対応を保存して、件数・重複・活動日・合計点を照合する。実DBの移行は本タスクで行っていない。

9. 今回のデモでできること・残ること

できること：トップの活動表示、5エリアのマップ/一覧切替、教室からカード/教材画面、共通メニューと現在地、カテゴリ横断リンク、プロフィール例の端末内保存、活動ロードマップの状態別絞り込み、既存の交流マップとの往復。成長表示は既存デモの端末内ポイントと連動。

未接続：実会員資格、実動画・素材ファイル、実予約、写真からのAI生成、実Chatwork、Supabase、活動ロードマップ自動判定・承認・ポイント同期。プロフィール例は新しいポータル内だけで保存し、旧交流デモの架空人物名は変更しない。活動ロードマップ状態は説明用の固定データで、プロフィール保存やリンク移動だけでは達成にしない。

次に確定するもの：素材集の棚卸しと公開範囲、会員の利用資格、最初に導入する活動ロードマップ、正式な配点と成長閾値、データ移行の会員ID対応、各エリアの最終アート。最新の全体構成はこのv0.11を優先し、詳細の既存ルールは統合仕様書を参照する。
