共通の入口から、学習・交流・AIへ。

「全員で勝つ」をミッションとするPLCポータルの統合動線案。田中祐一AIの独自ブラウザ会話画面をなくし、会員認証・MCP接続管理・教材・プロフィールをPLCポータルの配下に整理する。今回の実装は架空データの操作デモであり、本番認証・実会員・教材・外部投稿の移行ではない。

1. 名称と場所

全体の名称は「PLCポータル」。PLCパークはその中の3Dキャンパスの愛称。学習ルーム、AI接続ルーム、コミュニティラウンジ、マイスタジオへ入室する。AI資料・スキル・導入ガイドの置き場は「PLC AIライブラリ」。田中祐一AIはMCP経由で利用する機能名として維持する。

3Dは建物のタップで部屋へ入る目的別ナビゲーション。入室するとページ全体の背景、3D室内、利用メニューを切り替える。見回しと拡大縮小はできるが、キャラクターの自由歩行やマルチプレイヤーは今回の範囲外。2D一覧と通常メニューでも同じ機能に到達できる。今回の3Dは画像ではなく、Three.jsで描画した形状とクリック判定を使う。

2. 認証はPLCポータルに集約する

会話画面の廃止と認証基盤の廃止を分ける。確認した既存コードでは、ポータルのログアウトがブラウザセッションの削除処理を呼び、Cookieを消していた。現行の共通処理を依存関係ごと整理し、PLCポータルの会員認証として引き継ぐ。今回その本番コードを変更していない。

区分用途終了・更新
ポータルのログインセッション教材や会員画面を開く本人認証。HttpOnly Cookie等で管理。このブラウザからのログアウトで終了。
MCPの認可会員が特定のAIクライアントへ与えた利用権限。接続解除・資格失効で取り消す。ポータルログアウトでは継続する案。
アクセストークン／更新資格MCPへの各リクエストを認証。対象サーバーと権限を限定。短期トークンを更新。更新資格がなければ再認可。デモの15分は例示値。
MCP通信セッション必要な方式での通信状態。認可や会員IDの代わりにはしない。通信終了を権限取消と混同しない。
AIクライアント側のログイン外部AIサービス自身のアカウント。PLCからのログアウトや接続解除だけでは終了しない。

初回接続の流れ

  1. PLCポータルへログインし、在籍・契約・有効な機能を照合する。
  2. 接続ガイドから対応AIクライアントのMCP設定へ進む。対応プラン・手順は実機検証したものだけを案内する。
  3. クライアントが認可を開始し、PLCのログイン・許可画面へ戻る。未ログインならそこで本人認証する。
  4. クライアント名、会員、要求権限を表示し、本人が許可。取消時は権限を発行しない。
  5. クライアントへ戻り、認可コード等を交換してMCPを利用。トークンをURLや公開画面に出さない。
  6. PLCポータルで接続先・最終利用・許可範囲・解除を管理する。

認可はMCP公式のHTTP認可仕様を基準にする。会員ごとの権限、対象サーバー、期限を各要求で確認する。クライアント実装と互換性を照合し、共通の秘密キーを全員へ配布しない。

ログアウトと解除の操作

「ログアウト」はポータルのブラウザセッションを終了し、MCPの認可は残す。「この接続を解除」は該当する認可と更新資格を取り消す。「接続も解除してログアウト」は両方を行う。退会・停止はMCP利用も拒否する。短命JWTだけでは即時解除できない場合があるため、サーバー側の認可状態・失効時刻を各要求で照合し、古いトークンでも解除を迂回できない構成を採る。開始済みの処理の扱いは取消可否に応じ別途定める。

本番移行は、共通認証の分離→新しい接続方式の実機検証→既存ユーザーへの案内と再認可→会話履歴の参照・保存方針の確認→旧会話URLから接続ガイドへの案内→利用確認後の旧UI停止、の順とする。既存認証情報を名称変更だけで新しい方式へ使い回さない。

3. 動画の70％視聴でポイント

「最後に到達した秒数÷尺」ではなく、「再生した区間の和集合の長さ÷確定した尺」を使う。10分の動画なら、飛ばしていない異なる区間を7分再生したときに70％。同じ2分を何回見ても視聴範囲は2分のままとする。

Cloudflare Stream Player APIの再生時刻・尺・再生／停止・シーク等のイベントを利用する。視聴判定はポータル側の機能であり、Cloudflareが会員ごとのポイントや学習理解度を自動認定するわけではない。Cloudflare公式 Player API

条件提案ルール
基準70％で学習ポイントを1回付与。95％で視聴完了表示。理解度や習得の保証とはしない。
停止・シーク・バッファ待ち再生されていない区間は加算しない。シーク前後を一本の視聴区間でつながない。
倍速2倍まで許可。10分教材を2倍速で3.5分見れば7分の内容区間として扱う案。倍率変更時は計測基準を更新。
バックグラウンド初期案は非表示タブの区間を対象外。PiPや音声中心教材は別条件を設計し、黙って対象に混ぜない。
通信・再開停止・離脱時と定期的に区間を送信。受信番号と再送IDを持ち、未同期は「確認中」。再読込み・別端末はサーバーの和集合へ統合。
70％達成サーバーが付与済みを確認して確定。失敗中に画面だけ加算しない。
教材差替え・同一動画会員ID＋学習対象ID＋評価バージョンを一意キーにする。同じ動画の別コース掲載で二重付与しない。差替えの再獲得可否は運営が決定。

本番の記録と判定

サーバーが会員と教材閲覧権限を照合し、必要に応じて短期の署名付き再生URLを発行する。Cloudflare公式の視聴制限を参照。ブラウザは再生セッションID・連番・時刻・尺・速度・再生状態・可視状態・区間を送る。サーバー側の教材尺、受信間隔、許容速度、同時再生、重複・再送・異常値を検査し、区間をマージする。ポイント台帳の一意制約と同一トランザクションで1回だけ付与する。

ブラウザイベントだけでは改ざんや「見ずに再生」を完全には防げない。ポイントの価値に応じて異常な進み方の保留、同時再生制限、短い振り返りや確認問題を組み合わせる。自己申告の完了ボタンで自動代替せず、イベント取得不能時は運営確認の別経路とする。

今回のデモはCloudflare公式ページに掲載された公開サンプルを埋め込む。実PLC教材や会員ごとのサーバー記録は未接続。判定テストは10分教材の架空記録を別モードで再現する。公開サンプルとテストを切り替えると視聴テスト記録を初期化する。学習30点・アウトプット20点は提案値。

4. 学びの共有とポイント

動画の下に「気づいたこと・次に試すこと」を置く。本人が文章を編集し、学びの記録を保存できる。続けてX／Facebookへ共有できるが、運営による代筆・自動投稿は行わない。

XはWeb Intentで本文と#PLCを入れ、本人が投稿画面で編集・確定する。#PLCはハッシュタグであり、@アカウントのメンションとは別。X公式の投稿ボタン仕様

Facebookは本文をコピー→共有画面で本人が貼り付けるUIとする。本文の自動入力を必須要件にしない。今回Facebook公式仕様ページは取得制限で本文確認できず、実アプリ・ブラウザでの共有画面は本番前の検証対象とする。共有URLは誰でも見てよい紹介ページだけとし、会員限定本文、動画URL、署名付きURLを含めない。

投稿画面を開いた／閉じた、コピーした、URLを貼った、だけでは投稿完了を証明できない。APIで確認できる範囲・権限・費用は別途検証する。未連携の初期運用では本人の学びを確認し、投稿URLは任意記録とする。

今回の提案：70％視聴の学習ポイントに加え、自分の言葉でのアウトプットを確認後に追加ポイント。SNS公開でもポータル内の記録でも同額とし、同一教材1回、複数SNSへの投稿は重複加点しない。投稿そのものへの追加報酬を必須にする方式は、各SNSの規約・開示条件と検証方法を確認後に別途決定する。称賛の強要、いいね数への連動、大量の同文投稿は評価条件にしない。確認後の取消も台帳の履歴で扱う。

5. 在籍・活動・キャラクター

在籍日数、今期の活動日数、視聴基準達成数、実践数、仲間への支援数、部活動完走数、T／LTTを別々に表示する。長期在籍がそのまま実力や貢献を意味する総合点にはしない。本人が公開した項目だけを相手のプロフィールへ表示。最終ログインや相談内容の詳細は非公開の運営情報として扱う。

在籍日数は日本時間の日付で、在籍区間を合計し休止区間を除く案。入会日は0日、翌日で1日。再入会・休会・契約切替は区間台帳で管理する。デモは入会日と休止日数の簡略計算、基準日は2026/10/6。未照合の過去期間は「確認中」と表示し、推測で日数を補わない。

入会時・在籍90日・365日などでキャラクター／衣装の選択肢を増やす。ここは提案値。解放は見た目の特典に限定し、教材・相談権限は契約情報で管理する。本番では解放済みのコレクションを履歴に残し、休止で没収しない。デモの条件変更はルール検証用に未解放へ戻る動作を含む。支援実績による小物、部活完走のバッジなど、在籍以外の獲得経路も設ける。

6. 本番に接続するために必要なもの

  1. PLCの認証・会員資格・接続先MCPの正本と担当。現行利用者を維持する移行手順。
  2. 検証用のCloudflare Stream教材ID、再生許可、教材尺、会員と視聴記録の保存先。既存Cloudflare全件を確認したとは扱わない。
  3. 視聴・アウトプットの正式配点、確認担当、ポイント取消、教材差替えのルール。
  4. SNSの公開紹介URL・OG情報、共有導線の端末検証。外部投稿への独立報酬を導入する場合の規約確認。
  5. 入退会・休止履歴の正本、公開設定、解放済み特典の引継ぎ。

7. 受入条件

ポータルログアウトとMCP解除の差、認可拒否、期限切れの更新／再認可、資格失効時の拒否を確認する。動画は69％では未付与、70％で1回のみ、シーク・再送・再視聴・非表示中の不正加算なし。共有ボタンだけでは加点せず、承認の再実行でも二重加算なし。在籍89／90日・364／365日の境界と、本人の公開設定を確認する。本番ではこれらをサーバー側と実クライアントで検証する。
