AppleのMacページを実測し、PLCの毎日の使いやすさへ翻訳する。画像・カテゴリの順序・基本配置を維持して、書体、文字階層、余白、操作の表現を比較できる状態にしました。

変更前と改善版を切り替える →改善版を使う →

外部サイトの評価は観察に基づくデザイン上の判断です。Appleの制作意図や内部基準を断定するものではありません。Apple全ページの解析ではなく、指定Macページの主要な見出し・製品カード・行動導線を対象にしています。

01 / なぜシンプルでも美しく見えるのか

注意を向ける場所が、迷いなく決まっているから。見出し、画像、説明、行動の順番に強さの差があり、すべての要素が同時に目立とうとしていません。「文字が大きい」「余白が広い」という単独の性質より、隣り合う要素の比率と一貫性が効いています。

観察する軸Appleから読み取れる原則PLCで再現する方法
文字の階層見出し・製品名・操作・補足で大きさが明確に分かれる。見出しは極太一辺倒ではない。本文16pxを基準に、主見出し約52px、セクション32px、カード23px。太さ400/500/600を中心に。
余白の意味同じ内容同士を近づけ、次の話題へ進む境界を広くする。見出しと説明8〜10px、説明と操作16〜22px、セクション間28〜36px。均等な空白にしない。
画像の主役製品の輪郭や質感が読み取れ、背景が主役を邪魔しない。今回は風景を維持。次段階ではサムネイルの密度と主役の位置を検討。文字変更だけで世界観の問題が解決したとは扱わない。
色と面白と淡い中間色が基盤となり、色は画像と行動の識別に働く。本文は濃い中性色、カテゴリ色は位置と導線に使う。カードの輪郭線と強い影を削る。
ボタンとリンク同じカードでも塗りボタンと文字リンクで重要度が違う。学習の続きは塗りボタン。探索は文字リンク。内部移動→と外部移動↗を区別。
整列画像・見出し・説明の基準線が揃い、繰り返しに秩序がある。カード内の文章と行動を別に整列。説明の固定高さをやめ、下部の操作を揃える。
動き操作と状態の変化を理解できることが先。静止状態の階層が成立している。カードの上下移動と画像拡大を外す。色・影の短い変化、明確なフォーカス。演出を減らすOS設定に対応。
文章見出しと短い説明で一つの意味を伝える。ラベルの意味を統一し、長い見出しの改行位置を調整。今回の比較では内容をほぼ変えず書体と余白の効果を分離。

「AIが作ったか」は見た目だけでは判定できません。ここで減らすのは、どのサービスにもそのまま差し替えられるような、強弱の乏しい部品の並びです。

ボタン色はRGB(0,113,227)、文字リンクはRGB(0,102,204)。PLCはその青をコピーせず、同じ「役割の分離」を緑系で使います。

PLCは毎日使う会員サイトです。Appleの商品紹介の80px見出しや大きな上下余白をそのまま使うと、行動への距離が増えます。見出しの対比を残しつつ、上部ナビとパンくずの高さを抑えています。

03 / フォントの正体と、現実的な選択

AppleページのCSSでは、見出しに "SF Pro JP", "SF Pro Display", "SF Pro Icons", "Hiragino Kaku Gothic Pro", …、操作・本文系に "SF Pro JP", "SF Pro Text", … が宣言されていました。これは候補順の確認であり、各文字が最終的にどのフォントファイルで描かれたかまで確定する値ではありません。

候補費用・使い方PLCへの判断
システム書体＋ヒラギノ利用者の端末にある書体をCSSで指定。フォントファイルは配布しない。今回の標準。Apple端末で馴染みある表示。端末間で差がある。
Noto Sans JPOFLで商用Web配信可能。400〜700の可変フォントを自己配信。無料の推奨比較案。漢字・かな・英数字を全端末で統一しやすい。Apple書体と同一ではない。
ヒラギノWebフォント有料配信サービスなど。PC用書体購入とWeb配信権は別。端末を問わずヒラギノへ統一したい場合の候補。購入・契約は未実施。
InterOFL。UI向け欧文、text/displayのoptical sizeを持つ。Notoと組み合わせる欧文候補。今回の比較は原因を絞るため追加しない。
Zen Kaku Gothic NewOFL。日本語ゴシック。穏やかな独自性の対抗候補。今回未導入。

SF ProのダウンロードファイルをPLCへコピー配信しません。無料ダウンロードと一般Webサイトでの再配布許可は別です。端末内のsystem-uiを使うこととも区別します。

04 / PLCの実装ルール

  • PCのセクション見出し32px、カード見出し23px。狭いPC幅では長い日本語ラベルに合わせ20px。
  • 本文16px、カード説明15px、操作14〜16px。スマホの狭い2列カードは見出し17px、説明14px、リンク13pxを下限の目安とする。
  • 見出し600、本文400、状態や主要操作500。全体を太字にしない。
  • 日本語本文の字間は標準。欧文風の強いマイナス字間や全文の詰め組みは使わない。
  • 主要操作は44px以上の領域。カードは全体のリンクと未完了ボタンを別々に操作できる。
  • スマホの見出しと素材集リンクを縦に分離。「すか？」だけが残る折り返しを防ぐ。
  • ホームのカテゴリ順・写真・活動値・基本配置は維持。下層の教材カードはスマホ1列にして読みやすさを優先。
  • 塗りボタンは丸型、リンクは矢印と下線の反応、キーボードのフォーカスは青い輪郭。色だけに依存しない。
  • カードが毎回浮き上がる動きを廃止。ページ内容は短いフェード。移動・操作を待たせる演出は追加しない。

05 / 比較と検証

同じ画像・情報・カテゴリ配置の「変更前」と「改善版」を切り替えられます。さらに改善版内で書体を切り替えると、レイアウトの効果とフォントの効果を分けて確認できます。

  1. まず文字を読まず、最も大事なものが一つに見えるか。
  2. 説明・リンクが小さすぎず、読んで押すまで迷わないか。
  3. 同じ端末・同じ表示幅で、学習の続きと目的別入口への距離を比較。
  4. ホームから教材、未完了一覧、プロフィールへ進み、戻る。
  5. 390pxと狭い320pxで、長い日本語ラベルや操作の重なりを確認。
  6. Notoへ切り替えて文字の折り返し、欠字、文字の読み込みによる変化を確認。

独立エージェント2名による書体調査・画面レビューを実施。スマホの末尾孤立を修正。320px・390pxで横はみ出しなし、Notoの読み込み、日本語表示、メニュー→学ぶ→一覧→教材選択、前後切替と書体切替を確認。前後比較の活動値は同一ブラウザ状態でLv.12 / 1,190 LTT / 240 Tの一致を確認。過去スクリーンショットの異なる活動値は比較根拠にしません。

独立レビューで残った課題：スマホの5枚目のカードが半幅で残ること、個別タスク一覧までのスクロール、精密な風景5枚の情報密度。今回は配置と画像を固定する比較条件を優先し、これらを解決済みとは扱いません。

Appleより優れている、あるいは万人にとって見やすいと実証したものではありません。実会員による操作テスト、Windows・Android実機、弱い回線での評価は別途必要です。今回の目標は、実測可能な文字階層と動線の改善です。
