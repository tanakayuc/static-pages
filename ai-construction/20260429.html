このドキュメントは、theleadpromotion のフォルダの中身がどういう構造になっているか、CursorやClaude Codeを使うときに「どこを見ればいいの？」が分かるようにまとめた案内です。

CursorもClaude Codeも触ったことがない人でも分かるように書いていますので、安心して読んでくださいね。

まずは前提の話

Cursor と Claude Code って何？

両方とも「AI と一緒に作業ができる文書編集ツール」みたいなものです。
僕（田中）の会社では、人によってどっちを使うかが違うんですよね。

  • Cursor を使っている人
  • Claude Code を使っている人

このドキュメントは、両方のスタッフが同じ業務をできるようにするための説明書になっています。

何が問題だったか

実は2026年4月までは、こんな状態でした。

「あれ？このスキル、Cursor 側にしかないの？」
「議事録の作り方、ファイルが何個もあって、どれが正しいんだろう？」

こういう「同じ業務なのに、ツールごとに違うファイルを見ないといけない」状態だったんですよね。
これだと、ツールが違うだけで、できることが違ってくる。
おかしいですよね。

それで「全員が同じ業務マニュアルを見て動けるようにしよう」と整理し直したわけです。

全体の考え方（4つの場所）

ファイルの種類を、4つの場所に分けて整理しています。
会社の組織でたとえると、こんな感じです。

1. 本社（業務マニュアルの正本がある場所）

業務の正本（しょうほん。ホンモノの業務マニュアル）を置く場所です。
Cursor を使っていても、Claude Code を使っていても、最後にはここを見ます。

フォルダ 何が入ってる？
/skills/ 業務の手順書（18個のスキル）
/knowledge/ 判断のときに参考にする基準・知識
/agents/ AI担当者の人格・判断基準（9名分）
/configs/ 人格カルテ（不変のDNA。誰が語るか・哲学・実績・文体）

ポイント：編集するときは、必ずここを直してください。

2. 現場の入口（ツールから業務を呼び出す入口）

CursorやClaude Codeから業務スキルを呼び出すときの「入口」です。
中身は薄くて、「本社のここを見てね」と書いてあるだけ。

フォルダ 誰が使う？
.cursor/skills/ Cursorを使う人
.claude/skills/ Claude Codeを使う人
.claude/agents/ Claude Codeで「議事録担当を呼び出して」みたいなときに使う

ポイント：ここは触らなくて大丈夫です。
本社が更新されたら、毎日朝6:30に自動で「コピー」がここに反映されます。

3. 共通の社則（ツールが起動時に自動で読むルール）

CursorやClaude Codeを開いたときに「これだけは守ってね」というルールが書いてあります。

ファイル 誰が読む？
CLAUDE.md Claude Codeが起動するときに自動で読む
.cursor/rules/ Cursorが起動するときに自動で読む

両方に同じ内容が書いてあります。
ルール（書き方の基本ルール）は、CursorとClaude Codeで揃えておかないと、できあがるものが変わってきちゃうので、両方に同じものを置いている、ということですね。

4. 倉庫（実際の業務データの保管場所）

実際の業務データが置いてある場所です。

フォルダ 何が入ってる？
21_プロジェクト一覧/ クライアント案件のデータ・成果物
22_コミュニティサポート/ PLC運営・受講生サポート・会員サイト
0_データ原本/ Zoom録画・Chatworkログ・Loom動画など、自動で集まる生データ
02_ツール/ 業務を自動でやってくれるプログラム集
97_ザ・リード事業/ 事業運営のドキュメント

「スキル」「ナレッジ」「ルール」って違うの？

このあたり、ちょっとややこしいんですよね。
シンプルに言うとこんな違いがあります。

ナレッジ スキル ルール
どんなとき使う？ 「正解は何？」を調べたいとき 「どうやればいいの？」と手順を確認したいとき 「いつもこう書こう」という共通ルール
例え 教科書・参考書 業務手順書 就業規則
例 「広告のCPA目標は事業者向けで4,000〜8,000円」 「広告は3本配信→3日待って→ダメなら入れ替え」 「文章で太字を使わない」
場所 /knowledge/ /skills/ CLAUDE.md と .cursor/rules/

迷ったらこんなふうに考えてみてください。

  • 「これって AI が判断するときに必要な情報？」 → ナレッジ
  • 「これって AI が業務をやる順番？」 → スキル
  • 「これって毎回守る書き方のルール？」 → ルール

実際に使うときの流れ

Cursor を使っている人

  1. Cursorを開くと、.cursor/rules/ の中のルールが自動で読み込まれます（書き方の共通ルール）
  2. スキルを呼び出したいときは、スキルの名前（「Loom取得」とか）を指示します
  3. すると .cursor/skills/Loom取得/ が起動して、本社（/skills/Loom取得/）の中身を見て動きます

Claude Code を使っている人

  1. Claude Codeを開くと、CLAUDE.md が自動で読み込まれます（書き方の共通ルール）
  2. スキルを呼び出したいときは、.claude/skills/Loom取得/ を起動 → 本社の中身を見て動きます
  3. 専門の担当者を呼びたいときは「議事録担当を呼んで」のように指示すると、.claude/agents/minutes-writer.md が起動します

GitHub で見るとき

スタッフが GitHub でファイルを見たいときは、こう見ればいいです。

  • 「業務がどう動くか」を知りたい → /skills/ を見る
  • 「判断基準」を知りたい → /knowledge/ を見る
  • 「ルール」を知りたい → CLAUDE.md または .cursor/rules/ を見る
  • 「人格カルテ（誰が語るか）」を知りたい → /configs/<ホルダー名>/ を見る
  • 「案件の基本情報（ファネル型・ターゲット・見せ方）」を知りたい → 21_プロジェクト一覧/<案件>/マスターデータ/ を見る

編集するときのルール

ここ大事なところです。

業務スキル・ナレッジを編集するとき

/skills/ /knowledge/ /agents/ /configs/ の中だけを直してください。
.cursor/skills/ や .claude/skills/ は触らないでください。
こちらは「コピー」みたいなものなので、編集しても翌日6:30に上書きされて消えちゃいます。

ルールを編集するとき

CLAUDE.md を直したら、必ず .cursor/rules/ の対応するファイルも直してください。
逆も同じです。
両方に同じ内容が入っていないと、CursorとClaude Codeで動きが変わっちゃうので。

どのファイルがどのファイルに対応しているかは、CLAUDE.md の「ルール索引」を見てください。

スキル・ナレッジを編集すると、自動で何が起きるか

/skills/ を編集すると、毎日朝6:30に自動で動くプログラムが、その変更を .cursor/skills/ と .claude/skills/ のコピーに反映してくれます。

すぐに反映したいときは、自分で実行してもOKです。

# ズレてるかチェック
python3 02_ツール/開発支援/3層構造_同期監視.py

# ズレを修正
python3 02_ツール/開発支援/3層構造_同期監視.py --apply

2026年4月の整理し直しで何が変わったか

整理する前

  • .cursor/rules/ に45個もファイルがあって、業務の手順と書き方ルールがごちゃ混ぜ
  • .cursor/skills/ と .claude/skills/ で、内容が違うスキルがあった
  • 「どこを見ればいいか」がスタッフによってバラバラだった

整理した後（今）

  • 業務スキルは全部 /skills/ に集めた
  • ナレッジは /knowledge/ に整理（コピーライティング・議事録・メルマガ等）
  • .cursor/skills/ と .claude/skills/ は薄いコピーになって、毎日自動で同期される
  • .cursor/rules/ は19個まで減って、書き方の基本ルールだけ残した
  • CLAUDE.md を1179行から146行に縮めた（詳細は rules/ フォルダに分散、入口は AGENTS.md に統合）
  • /configs/ は「人格カルテ（不変のDNA）」だけを置く場所に整理。案件ごとに変わるパラメータ（ファネル型・コアメッセージ等）は 21_プロジェクト一覧/<案件>/マスターデータ/案件マスター[_<案件名>].md に置く形にした。configは「設定（不変）」、案件マスターは「データ側のパラメータ」という分担になった
  • 案件を上から下まで組み上げる土台スキル /skills/プロモーション構築/ を新設。「プロモーション構築を進めてください」と一言で、人格カルテ・案件configの整備から10ステップ進行までが動く

困ったときに見る場所

「あれ、どうすればいいんだっけ？」となったら、以下を見てみてください。

業務の手順を知りたい

  • /skills/ の該当スキルを見る
  • 例：「Loom取得ってどうやるんだっけ？」 → /skills/Loom取得/SKILL.md

判断基準を知りたい

  • /knowledge/ の該当ナレッジを見る
  • 例：「コンセプトを作るときの3C分析って何？」 → /knowledge/スキル別/コンセプト設計/3C分析の判断基準.md

書き方のルールを知りたい

  • AGENTS.md の「ルール索引」を見る（CLAUDE.md はここへのリダイレクト）
  • 例：「ファイル名はどう決めるんだっけ？」 → rules/ファイル命名規則.md

スキルが動かない・ズレてる気がする

  • 同期チェックを実行してみる
  • python3 02_ツール/開発支援/3層構造_同期監視.py
  • 結果がおかしければ、田中さん（または開発担当）に相談

これから取り組みたい改善のアイデア

これから取り組むといいかな、と思っているものです。

すぐ着手できそうなもの

  • 計画モードを積極的に使う：複雑な作業のとき、AIに最初に計画を立てさせる機能。やってみたい
  • 記憶機能の整備：やりとりをまたいでAIに覚えてもらう機能

じっくり検討するもの

  • 出力スタイルの切り替え：タスクごとに「セールス分析モード」「議事録モード」みたいに出力の見た目を切り替える
  • 自動学習機能：「うまくいった」「失敗した」を AI が自動的に学習する仕組み
  • 複数AI並列処理：複数のAIに並列で違う作業をやってもらう機能

MCPの整理について

MCPっていうのは、AIに外部のサービス（utageとかGoogleカレンダーとか）と連携させる仕組みのことです。
